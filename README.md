# Fantasy Football AI Manager

A fantasy football decision engine for historical league simulation, evolutionary draft strategy, ESPN league sync, lineup optimization, custom projections, waiver recommendations, trade suggestions, and a desktop dashboard.

## Running the project locally

Activate the virtual environment, then run:

```powershell
python main.py
```

## Historical data processing

The supported walk-forward manager window is 2001–2024 with 2025 held out. The
1999–2000 files provide the two-season lookback required by the projection features.

Audit and download the required weekly files:

```powershell
python -m scripts.audit_historical_data
```

To rebuild the cleaned 2021 processed Parquet cache:

```powershell
python -m scripts.rebuild_2021_processed_season
```

Rebuild the leakage-safe draft projection checkpoint:

```powershell
python -m scripts.train_draft_projection_nn
```

Rebuild the leakage-safe weekly projection checkpoint:

```powershell
python -m scripts.train_weekly_projection_nn
```

Then train the manager across the expanded historical window:

```powershell
python -u -m scripts.train_manager_policy_real_seasons --start-season 2001 --end-season 2024 --holdout-season 2025 --population 30 --generations 12 --selection 10 --consistency-penalty 0.25 2>&1 | Tee-Object -FilePath logs/training_overnight.log
```

`Tee-Object` keeps progress visible in the terminal while saving the same output to a log file.
Completed generations are also checkpointed under `data/models/manager_training_checkpoints/`.

Evaluate the trained policy across multiple seasons:

```powershell
python -u -m scripts.evaluate_real_policy_walk_forward --start-season 2021 --end-season 2025 2>&1 | Tee-Object -FilePath logs/policy_multi_season_evaluation.log
```

## Modular policy training

The modular policy separates projection inputs from draft, lineup, waiver, and
trade decisions. It first imitates the transparent draft teacher, then evolves
the policy through multi-season self-play. This is the recommended experimental
path; the existing manager checkpoint remains available as a compatibility
baseline.

Run a small smoke experiment:

```powershell
python -u -m scripts.train_modular_manager_policy --start-season 2021 --end-season 2021 --population 10 --generations 1 --selection 3 --epochs 1 2>&1 | Tee-Object -FilePath logs/modular_policy_smoke.log
```

The modular checkpoint is written to `data/models/modular_manager_policy.pt`.
Projection uncertainty is exposed through `models/projection_ensemble.py`, and
strict chronological folds are generated by `evolution.walk_forward`.

For a long run, add `--draft-exploration-rate 0.06` to preserve draft-room
diversity. Add `--transaction-ablation` to the command when you want the final
report to compare neural transactions against the genome baseline and against
no transactions. Those comparisons are written under
`final_evaluation.candidates[*].transaction_ablation` in the JSON report.
Transaction replay rewards include the downstream weeks after the original
waiver or trade, so the policy is trained on the full value of a move.

### Optional local coach model

The numerical policy and simulator remain responsible for draft, lineup,
waiver, and trade decisions. An optional local language model can explain those
recommendations and summarize structured news/context, but it cannot submit or
override a transaction. The provider is disabled by default and uses an
OpenAI-compatible local endpoint when enabled:

```powershell
Copy-Item .env.example .env
# Set FFB_LLM_ENABLED=1 after starting your local model server.
```

The coach falls back to a deterministic explanation if the local model is
disabled, unavailable, or returns malformed output. This keeps simulations and
the desktop app usable offline.

Add historical lineup, waiver, and trade replay records to the offline stage by
including `--collect-season-replay` in the modular training command. Those
records use only pre-decision projections and receive rewards from later weekly
player outcomes.

Run true cutoff-by-cutoff manager evaluation with a small smoke configuration:

```powershell
python -u -m scripts.evaluate_manager_walk_forward --start-season 2021 --end-season 2023 --minimum-training-seasons 1 --population 10 --generations 1 --selection 3 --initial-policy data/models/modular_manager_policy.pt 2>&1 | Tee-Object -FilePath logs/manager_walk_forward.log
```

Each fold trains only on seasons before its validation/test seasons, saves its
own checkpoint, and reports the next unseen season separately.

## Launching the UI prototype

The first desktop shell is intentionally offline and uses placeholder data.
Launch it from the project root with:

```powershell
python -m scripts.run_ui
```

It includes Home, Draft Assistant, Lineup Coach, Waiver Wire, Trade Center,
Models & Reports, and Settings views. ESPN and model connections will be added
in later milestones.
